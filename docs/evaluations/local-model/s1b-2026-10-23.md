# Local model run S1b (23 Oct 2026): why a visible paid order did not become delivered work

**Run:** scenario `s1-order-and-correction` on Qwen3.5-2B Q6_K (the CPU **diagnostic** model, not the 9B target), llama.cpp
b11838 on 127.0.0.1:8090, 12-vCPU development VM. 15:46:01–16:23:40 UTC (37.5 min), 7 turns, 108 model calls (107 ok, 1
provider timeout), 1,800,680 prompt tokens and 14,824 output tokens, **£0 / 0 µ¢**. Egress tripwire (process-level, every
Node process of the run): **0 non-loopback connection or DNS attempts**. Verdict: `poor_decision` — the paid order was not
delivered. Evidence: [`s1b-2026-10-23/`](s1b-2026-10-23/) (packets, step log, carried record, calls, obligations,
results; the analysis needed no model call).

What this shows: local-only operation works; **competent fulfilment does not yet**. It does not show that the 2B model has no
weaknesses: it has many (below). Nor does it say anything about the 9B model on the GPU; that has to be demonstrated.

## The question: what prevented the visible paid order from becoming completed work?

Four platform defects, plus the model's own weaknesses. Each defect is confirmed in the evidence below:

1. **The packet steered away from the order (platform).** From turn 2 onwards, every packet carried the order line ("PAID …,
   its delivery is OWED") and `1 PAID ORDER(S) TO DELIVER`. But the wake brief's **objective** line said either the agent's own
   goal (`g1 "Execute find_opportunity: build MVP and launch"`) or "no open goal — assess what is worth doing". The packet's
   **next-move** line also said "No open decision and no execution path. Run ONE concise opportunity-identification cycle"
   (or "Your open goals are your execution path"). The order was visible, but it was never the objective, so the model did
   what the objective and the next move told it to do.
2. **Every file path the model chose was refused, and the refusal said nothing useful (platform).** The model wrote the
   order's files as `/workspace/gas_safety_checklist.txt` and listed `/workspace`: the common convention. The resolver
   refuses every absolute path, and the refusal said only "path must stay inside your workspace". That happened 7 times
   (write_file ×3, list_files ×3, read_file ×1), plus 5 identical list_files calls blocked as duplicates. The one relative attempt (`workspace/checklist.pdf`) pointed at a file it had
   never created. **No file was ever written, so nothing could be inspected or delivered.**
3. **Repetition was bounded per call, but not per turn (platform).** The loop guard refused each identical failed call. But
   turn 6 still spent 5 consecutive steps (about 25 s of model time each) receiving `FLEET_DUPLICATE_FAILED_ACTION` for the
   same `list_files /workspace`.
4. **The delivery obligation depended on the buyer not having written (platform; found in review).** In v112, `to_deliver`
   applied only to orders with no buyer message. Once the buyer wrote, the order became `unanswered` / `acknowledged`.
   Neither state said that delivery was still owed, and an answer marked `resolved` ended the obligation without a delivery.
5. **Model weaknesses (2B), shown by its calls:**
   - It retried `offer`/`venture` with arguments that kept violating the stated rule (`kind` at most 10 characters, then
     "product or service") 17 times over turns 2–3, plus one more blocked as a duplicate.
   - It called `web_search` 9 times after `FLEET_CAPABILITY_NOT_CONFIGURED` ("no web search provider is connected").
   - It passed the order's URL to `deliverable` as a workspace file (4×).
   - It invented `field_journal op read`.
   - It mistook `customers` for an order reader (`enquiryId` not found, 2×).
   - It wrote "OWEDED".

   Some of these will improve with a larger model. None of them should be assumed fixed.

## Repairs (this change set)

All of these are reversible code changes; none needs a privileged action.

- **Paths:** `/workspace/…` and the workspace's own absolute path now mean the workspace. Every escape check still runs on the
  rest of the path: no other absolute path, no `..`, no symlink out. A refused path says which form works: "paths are relative
  to your workspace — e.g. checklist.pdf or order/checklist.pdf …". `deliverable` given a missing file says to create it first
  (write_file, or exec for a PDF or spreadsheet).
- **The obligation cannot disappear:** every order obligation carries `deliveryOwed`, derived from the order's own status (paid
  and `to_fulfil` / `delivery_failed`) whatever the buyer has written. It survives a buyer message, an agent answer and an
  answer marked resolved; it ends only on delivery, fulfilment or refund. This is proven against PostgreSQL in
  `fleet-v100-obligations-pg`.
- **Obligation first, own goal second:** while a delivery is owed, the brief's objective is `DELIVER the paid order …`. The
  agent's self-generated goal appears separately as `your own goal, after that: …`. The packet's next move becomes the delivery
  task, replacing the opportunity / venture push for that wake. If something blocks the delivery, the agent is told to record
  the specific blocker and what unblocks it (`record_external_dependency`) and to tell the buyer; the order stays owed until it
  is delivered or refunded.
- **Bounded repetition per turn:** a turn whose last 3 steps did nothing but repeat already-refused actions is ended there
  (`FLEET_TURN_REPEATING`). It is carried, and the next wake is told that it was the agent's own loop and to change approach.
- **Compute bound kept:** the scenario's local cap returns to 120 calls/hour (it had been raised to 600 for local runs). Local
  inference avoids an invoice, not wasted hours.
- (Found while regression-testing: two `fleet-cognition` PostgreSQL tests had failed since the local_only default; that suite
  now opts into `cloud_allowed` like the other cloud-era suites.)
